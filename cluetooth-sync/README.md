# cluetooth-sync

Sync encrypted BLE scan blobs into Postgres/PostGIS, then export eligible scan
rows to WiGLE-compatible Bluetooth CSV batches.

## Payload routing

Every discovered URI is routed before decryption. Supported routes are:

- legacy Android `0.0.1` through `0.0.4` (suffixes allowed): sealed-box decrypt, outer Zstd decompress, then JSONL adaptation;
- schema v2 at `scans/v2/YYYY/MM/DD/<uuidv7>.parquet.encrypted`: sealed-box decrypt, then direct Polars Parquet read with no outer Zstd.

Every `schema=` scan path is rejected; only canonical nested `scans/v2/...` is Parquet v2, while `scans/v1/...`, other `scans/vN/...`, and malformed v2 paths never fall through to legacy decoding. Legacy is accepted only as one flat `scans/<supported-0.0.1-through-0.0.4-filename>.jsonl.zst.encrypted` object; nested, absolute, dot, traversal, and unsupported-version names are rejected. V2 routing validates canonical UUIDv7/date agreement; reading validates footer schema/identity, exact ordered dtypes (including Float32 accuracy), required non-null values, canonical MAC/signed-smallint bounds, paired finite ranged coordinates, and finite nonnegative accuracy semantics before binary `raw` is converted to lowercase hex for the existing staging transaction. Valid empty exact-schema v2 files are marked successful. Route, decrypt, decompress, metadata, schema, read, and insert failures are recorded once in the blob ledger and remain discoverable for retry.

Discovery deliberately performs a full `scans/` listing every cycle and skips only URIs already marked successful; there is no UUID/date watermark. `MirroredStorageClient` preserves nested object paths and resolves object and sidecar destinations beneath the resolved mirror root, rejecting existing symlink escape and unsafe components. Cache objects and size/SHA-256 completion markers are fsynced and atomically replaced; missing or mismatched markers force an upstream refetch instead of trusting a partial or bitrotted file. The cross-language plaintext fixture is under `tests/fixtures/payload-v2/` and is generated by production Rust code. A contract test also invokes production Rust sealed-box preparation with an ephemeral test recipient and proves PyNaCl decrypts the exact Parquet bytes. The sync deployment assumes one active pipeline process; discovery does not implement a cross-process claim/lease. Host fakes and encrypted database contract tests do not validate a real GCS bucket or Android/Firebase device path.

## WiGLE Uploads With Docker Compose

WiGLE uploads read already-ingested rows from Postgres. Run a sync first, or run
the upload against an existing database volume that already contains scans.

1. Copy the root environment template and fill in credentials:

   ```sh
   cp .env.example .env
   ```

   Set `WIGLE_API_KEY` to `base64(api-name:api-token)`.

2. Start the database and migrations:

   ```sh
   docker compose up -d postgres migrate
   ```

3. Ingest scans if the database is not already populated:

   ```sh
   docker compose --profile manual run --rm sync
   ```

4. Upload all pending WiGLE batches:

   ```sh
   docker compose --profile manual run --rm wigle-upload
   ```

   The service creates or resumes tracked batches until no eligible rows remain.
   Each batch is written as a temporary CSV inside the one-shot container,
   uploaded to WiGLE, and recorded with its WiGLE transaction id in
   `wigle_upload_batches`.

Useful overrides:

```sh
# Limit the number of scan rows claimed by each temporary CSV batch.
CLUETOOTH_WIGLE_BATCH_SIZE=1000 docker compose --profile manual run --rm wigle-upload

# Upload a specific existing batch.
docker compose --profile manual run --rm wigle-upload wigle upload --batch-id 12

# Retry an explicitly selected failed batch.
docker compose --profile manual run --rm wigle-upload wigle upload --batch-id 12 --retry-failed

# Check WiGLE processing status for uploaded batches.
docker compose --profile manual run --rm wigle-upload wigle status

# List tracked upload batches.
docker compose --profile manual run --rm wigle-upload wigle batches
```

By default uploads use WiGLE's non-donation mode. Pass `--donate` to
`wigle upload` only when the file contents should be marked for commercial-use
donation.
